# v0.11 内置环境与首次配置

本版随发布包提供 Windows x64 的 Python 3.12.10 和 41 个固定版本的离线依赖，包括 PyMechanical、请求接口、参数校验和图像支持。无需单独安装系统 Python，也不再依赖开发电脑的工作目录。

## 第一次启动

1. 完整解压发布包，保留 `.exe`、`_internal`、`runtime_payload` 和其他随附文件；双击 `Ansys力学助手_v0.11.exe`。
2. 点击右上角“模型 API 设置”，输入 API 根地址、模型名和密钥，点击“保存 API 配置”。
3. 程序切换到“环境检查”，自动检测系统、内置包、Python 依赖、用户目录及 Mechanical 安装。缺少或损坏的程序专用 Python 环境会用内置包配置，并重新检查模块与依赖一致性。
4. 程序验证 API 的工具调用协议，再让对话模型结合真实检查结果给出下一步建议。API 连接失败时，已完成的本机配置仍然保留，可按提示修正 API 后重试。
5. 点击“检查 Ansys 连接”，验证 Mechanical 是否能实际启动和响应。随后按“模型 → 约束与外力 → 网格与求解”操作。求解许可证需要在实际求解时验证。

首次配置仅在当前用户目录展开本程序专用环境，不需要管理员权限，不修改系统 Python 或系统 PATH。需要至少 512 MB 可用磁盘空间。Python 和依赖的配置过程不访问软件源；API 调用仍需要能访问所配置的模型服务。

## 环境检查与助手

- “检查并自动配置”：重新检查，发现可修复项时使用内置包恢复。
- “仅重新检查”：只收集状态，不安装依赖。
- “选择 Ansys 安装”：自动识别失败时，手动选择 Mechanical 2025 R2 的 `aisol/Bin/winx64/AnsysWBU.exe`。
- 在聊天中输入“检查环境，缺少依赖时使用内置包配置”，模型可以调用真实的 `environment_status` 与 `prepare_environment` 工具，不必先导入模型。
- 每次调用 Mechanical 工具前还会检查内置 Python 环境。程序不会定时向模型发送付费请求；需要时重新检查即可。

对话模型只可触发固定的检查和离线配置动作，不能生成任意命令执行，不能安装不在发布包中的包。环境检查不发送 API 密钥或系统环境变量。模型 API 收到的是结构化检查结果，可能包含程序路径、版本和错误描述。

“仅重新检查”不会触发模型自动修复；如需让模型进一步解释，可随后在聊天中提出。其他自动配置入口的模型说明不可用时，界面仍保留本机真实检测结果。

## 状态含义

| 状态 | 含义与处理 |
|---|---|
| 可自动配置 | 程序专用 Python 未部署或模块损坏，可用内置包重建 |
| 内置环境就绪 | Python 与依赖通过检查，可尝试连接 Ansys |
| 需手动处理 | 如缺少 Ansys 本体、未找到安装目录，需要安装或选定位置 |
| 阻断 | 如发布文件缺失、空间不足、目录不可写或系统不支持，需要先处理 |
| 软件连接通过 | Mechanical 已实际响应；不等于求解许可或工程结果已经验证 |

Ansys 安装介质、许可证及必须由管理员安装的系统组件不包含在 Python 包中，程序不会宣称自动补齐这些条件。内置包校验失败时停止配置，重新解压完整发布包后重试。

## 环境文件与维护

- 发布包的 `runtime_payload/` 保存官方 CPython 嵌入包、离线 wheels、固定版本/哈希锁定表和清单。
- 展开后的环境位于 `%LOCALAPPDATA%/AnsysMechanicalAssistant/runtimes/`，首次配置成功后保存本程序位置对应的环境指针。移动发布目录后会为新位置重新建立环境。
- 配置失败的尝试保留 `offline-install.log` 便于排查；失败环境不会覆盖之前成功的环境。修复不删除旧环境或用户工程。
- API 地址和模型名称保存在当前用户偏好设置中；密钥仍仅保存在程序内存中，退出后需重新填写。
- `runtime.json` 中不再包含开发电脑的绝对 Python 路径。

实现参考：[CPython Windows 嵌入式分发说明](https://docs.python.org/3.12/using/windows.html#the-embeddable-package)、[pip 离线安装参数](https://pip.pypa.io/en/stable/cli/pip_install/#install-no-index)。
